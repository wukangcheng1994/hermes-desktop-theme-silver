# Conversation bubbles and timestamps

This guide documents the combination used with Hermes Desktop v0.21.2: this repository supplies chat styling, while Hermes supplies native timestamps. No replacement chat engine or application-bundle patch is required.

## 1. Install the conversation theme

Follow the [installation guide](../README.md) and select Silver Studio or Porcelain Aurora. Both full desktop plugins include:

- Right-aligned user bubbles, up to 85% of their container width.
- Non-sticky user messages in normal chat, with the sticky prompt height clamp removed.
- Prose-style assistant replies with 1.65 line height and a 72ch paragraph limit; this is not a two-sided messenger bubble layout.
- Glass CSS on the sidebar and composer, with separate HUD handling.

Source: [Silver Studio](../plugin.js) and [Porcelain Aurora](../porcelain-aurora/plugin.js). Search for `aui_user-message-root`, `aui_user-bubble-actions`, `sticky-human-clamp`, and `aui_assistant-message-content`. These styles do not modify history, model context, or sending behavior. Failed-message deletion, retry controls, and Bot-switch scroll restoration are not included.

## 2. Enable timestamps

Run on the machine hosting Hermes. First confirm that the command targets the intended Profile configuration:

```sh
hermes config path
hermes config get display.timestamps
hermes config set display.timestamps true
hermes config get display.timestamps
```

The last command should print `true`. To disable:

```sh
hermes config set display.timestamps false
```

Use Hermes's configuration writer; do not replace the entire config.yaml. This targets the Profile resolved by the current command environment, not every Profile automatically. For another Profile, specify its actual directory, for example on macOS/Linux:

```sh
HERMES_HOME="$HOME/.hermes/profiles/pr-bot" hermes config set display.timestamps true
```

Replace `pr-bot` with your Profile name. Custom Hermes homes and remote Bots require their actual directory and host. The basic `hermes config` commands also work in Windows PowerShell for the default Profile, but this project has not been tested on Windows.

Return to the target conversation. If the configuration is `true` but the UI has not refreshed, reopen the desktop app to reload it. Hermes defaults this option to off; the maintainer's configuration was verified as `true` for this guide.

## 3. Timestamp behavior and ownership

Timestamps are an existing Hermes display feature, not content generated by this theme:

- They use recorded message/tool times; missing or invalid times are not fabricated.
- This version uses local time formatting with millisecond precision on the timeline; some activities show start → end ranges.
- `display.timestamps` gates visibility. It does not insert timestamps into text sent to the model.
- This repository adds no timestamp-format selector, timestamp toggle implementation, or history migration.

## Verification and scope

Run `node check.mjs` for both plugins. In Sessions and Bots, verify right-aligned user bubbles that scroll without pinning; after enabling timestamps, records with valid times should display them. Layout CSS requires the full desktop plugin; the Marketplace package provides colors only and does not enable timestamps. Switching to another theme removes this layout, while setting `display.timestamps` to false hides timestamps. The two settings are independent.
